# 남은 작업과 현재 제약

2026-10-18 저장소 코드와 기존 기록을 대조했다. 코드상 제약은 실행으로 재현한 결과가 아니며, 운영 상태가 필요한 항목은 별도로 표시했다.

## 모바일 레이아웃

2026-08-19 운영 사이트에서 모바일 레이아웃이 깨진다는 보고가 있었다. 원인과 해결 여부는 재확인이 필요하다. 현재 작은 화면에서 1열로 전환하지만 사이드바 sticky와 헤더 고정 검색창 너비가 남아 있다. 실제 화면에서 검증한 뒤 수정할 것.

## 검색 갱신

- 재인덱싱은 `POST /api/search/reindex`와 `x-reindex-secret` 헤더를 사용하는 수동 방식이다. Notion 변경을 자동 감지하지 않는다. 배포 파이프라인·주기 실행 연동은 이 저장소에 없다.
- 공개 글을 추가·갱신하지만 기존 검색 문서를 삭제하지 않는다. 삭제·비공개 전환한 글이 인덱스에 남을 수 있다.
- 문서 등록 응답의 HTTP 성공 여부와 Meilisearch 비동기 작업 완료를 확인하지 않는다. 반환하는 `indexed`는 전송하려던 문서 개수로, 실제 반영 완료를 보장하지 않는다.
- 검색 서버 오류는 빈 결과로 처리하므로 장애와 검색 결과 없음을 구분할 수 없다.

## 홈 목록 페이지네이션

`getPublishedPostsPage()`는 원본 행을 `page * pageSize + 1`개까지 수집한 뒤 비공개 글을 제외한다. 비공개 행이 섞이면 페이지가 짧아지거나 뒤에 공개 글이 있어도 다음 페이지가 없다고 판단할 수 있다. 공개 글 개수를 기준으로 충분히 수집하도록 개선할 여지가 있다.

## 카테고리 이름 중복

트리 펼침 상태는 전체 경로로 구분하지만 URL·글 필터·개수 집계는 이름 기준이다. 서로 다른 부모 아래 같은 이름이 있으면 목록과 개수가 합쳐질 수 있다.

## 조회수·방문자 집계

두 기능 모두 구현되어 있다. 과거 “조회수 미구현”, “통계 mock” 설명은 더 이상 유효하지 않다.

- 조회수는 브라우저 쿠키로 24시간 동안 중복 증가를 억제한다. 쿠키 삭제·다른 브라우저까지 동일 방문자로 판별하지 않는다.
- 백엔드 조회수는 조회 후 증가시켜 저장한다. 동시 요청 시 증가분 유실이나 최초 행 생성 충돌 가능성이 있다.
- 방문 기록도 존재 확인 후 삽입하므로 동일 방문자의 동시 요청은 복합 기본 키 충돌 가능성이 있다.
- 방문 날짜는 UTC 기준이다. 한국 시간 자정 기준이 필요하면 변경해야 한다. 전체 수는 일별 합계가 아닌 고유 방문자 ID 개수다.
- 백엔드 실패 시 프론트엔드는 0으로 대체한다. 조회수 증가 실패 시에도 중복 방지 쿠키가 설정되어 24시간 동안 재시도가 억제될 수 있다.

## 포트폴리오 (의도적 보류)

헤더는 `/portfolio`를 링크하지만 해당 페이지가 없어 404가 된다. 블로그 완성 뒤 작업할 예정으로 링크를 유지하고 있다.

## 도입하지 않은 기능

- Redis: 초기 스택에 포함됐지만 현재 저장소에는 연동 코드가 없다.
- 방문 분석: Umami·Plausible은 후보이며 도입 코드는 없다. 현재 방문자 카운터와는 별개다.
- 관리자 인증·자체 에디터: Notion에서 글을 관리하므로 제거했다. 기존 mock 인증을 되살리지 않는다.
- 별도 좋아요: giscus 리액션으로 대체한다.
- RSS: 만들지 않기로 결정했다.
